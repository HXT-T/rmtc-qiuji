# 相关算法学习

[算法总览.md](算法总览.md) 介绍的是我们实际用到的算法。本文换一个方向：按同样的模块，介绍同类问题上常见的其他算法，作为开阔视野的学习笔记。

每个模块回答四个问题：
- 我们用了什么；
- 同类问题上还有哪些做法；
- 什么时候值得换；
- 去哪里读。

文献只列经典、容易查到的原始论文和教材。

---

## 0. 这个问题属于哪一类

用术语描述，RMTC 第二阶段是一个**多人、同时行动、部分可观测、有时间限制的一般和随机博弈**。

| 特征 | 术语 | 带来的难点 |
|---|---|---|
| 四队同场，不是你输我赢 | 多人一般和博弈（general-sum, n-player） | 纳什均衡不唯一，“最优”依赖对手 |
| 每 Tick 同时出动作 | 同时行动博弈（simultaneous-move） | 不能像下棋那样轮流搜索 |
| 9×9 视野 | 部分可观测（partially observable） | 必须对看不见的部分建信念 |
| 资源被拿光即止 | 零和的资源竞争 + 时间窗 | 价值随时间和对手位置衰减 |
| 每 Tick 0.5 s | 实时决策（anytime） | 算法必须随时能给出答案 |

同类的公开比赛（都是网格或地图上的多智能体资源竞争，很多有公开的优胜方案和赛后总结）：

| 比赛 | 和 RMTC 的相似处 |
|---|---|
| Google AI Challenge “Ants”（2011） | 网格、战争迷雾、采集食物、多人同场，最接近 |
| Halite I–IV（Two Sigma，2016–2020） | 采集资源、多人、零和资源池 |
| Lux AI（Kaggle，2021 起） | 资源采集 + 对抗，有部分可观测版本 |
| Kaggle Hungry Geese（2021）、Kore（2022） | 四人同时行动 |
| Pommerman（NeurIPS 2018） | 炸弹人式网格对抗，部分可观测，四人 |
| Battlecode（MIT，每年） | 多单位、部分可观测、计算预算限制 |
| microRTS、GVGAI | 研究用的实时策略与通用游戏 AI 平台 |

读这些比赛的优胜方案总结，是最快的学习方式：多数冠军是“规则 + 搜索 + 精心评测”，而不是纯学习。

## 1. 寻路

**我们用的**：Dijkstra。未知格当作可走、加小代价，地形变了就重算，没变就用缓存。

| 算法 | 要点 | 什么时候值得用 |
|---|---|---|
| A* | Dijkstra 加启发函数（例如曼哈顿距离），只搜向目标的方向 | 单源单目标、地图大。我们要“到所有格的距离”，所以 Dijkstra 反而合适 |
| D* Lite / LPA* | 增量重规划：地图局部变化时只修正受影响的部分。采用“自由空间假设”（未知即可走），和我们的做法相同 | 地图大、每步都有新发现、重算太慢时 |
| Jump Point Search | 均匀网格上跳过对称路径，比 A* 快一个数量级 | 大网格、单目标 |
| 流场（flow field） | 从目标反向算一次距离场，所有单位共用 | 很多单位去同一个目标（RTS） |
| 多智能体寻路 CBS | 冲突时分裂约束树，保证多车不撞 | 一队控制多辆车时 |

**延伸阅读**
- Hart, Nilsson, Raphael（1968）A*
- Koenig & Likhachev（2002）D* Lite
- Harabor & Grastien（2011）JPS
- Sharon 等（2015）Conflict-Based Search

## 2. 采集路线：定向越野问题

**我们用的**：第一阶段在资源全部已知时，用状态压缩 DP 求精确解，即 Held–Karp 思路。其他情况用“最近优先 + 2-opt”巡回，或束搜索。

我们的问题在运筹学里叫**定向越野问题（Orienteering Problem, OP）**：时间有限，选一部分点去拿奖励，使总奖励最大。它是 TSP 的“选点版”。

| 变体 / 算法 | 要点 | 对应我们的情形 |
|---|---|---|
| Held–Karp DP | O(2ⁿ·n²) 精确解，n ≤ 15 左右可行 | 第一阶段收尾，就是我们做的 |
| 2-opt、Or-opt、Lin–Kernighan（LKH） | 局部改进：反转一段路线，或移动一个点 | 巡回的改进；LKH 是 TSP 最强的启发式之一 |
| 迭代局部搜索（ILS）、自适应大邻域搜索（ALNS） | “破坏一部分再修复”反复迭代 | 点多、需要接近最优时 |
| 带时间窗的 OP（OPTW） | 每个点只在某个时间段内有效 | 资源会被对手拿走，相当于软时间窗；评测里的 thief 求的就是它 |
| 随机 / 动态 OP | 奖励或可用性是随机的，边走边更新 | 第二阶段的真实情形：存活概率就是随机时间窗 |
| 团队 OP（TOP） | 多辆车分工采集 | 一队多车时 |

**一个值得记住的结论**：随机 OP 里，“按期望值静态规划”和“随信息到来重新规划”之间可能有很大差距。这正是我们每 Tick 重新规划的原因。

**延伸阅读**
- Held & Karp（1962）
- Golden, Levy, Vohra（1987）定向越野问题
- Vansteenwegen, Souffriau, Van Oudheusden（2011）《The orienteering problem: A survey》
- Helsgaun（2000）LKH

## 3. 部分可观测下的探索与信念

**我们用的**
- 未见区资源的后验：剩余总值均摊到未见格。
- 领地权重。
- 前沿探索：新视野 / 代价。

| 方法 | 要点 | 和我们的关系 |
|---|---|---|
| 前沿探索（frontier-based exploration） | 去已知与未知的边界，机器人建图的经典方法 | 就是我们的探索前沿 |
| 信息增益 / 下一最佳视点 | 按“预计减少多少不确定性”选位置，而不是按“新看到几格” | 我们用“期望资源价值”代替信息量，更贴近得分 |
| 贝叶斯搜索理论 | 目标位置的先验 × 搜到的概率，搜索后做贝叶斯更新 | 未见区后验的更一般形式；二战找潜艇、找失事飞机都用它 |
| 占据网格、粒子滤波 | 用概率网格或一堆样本表示“东西可能在哪” | 可以用来跟踪看不见的对手（见 4） |
| POMDP | 在“信念状态”上做最优决策的完整框架 | 理论上最正确，精确求解不可行，通常用 5 的近似方法 |

**延伸阅读**
- Yamauchi（1997）前沿探索
- Thrun, Burgard, Fox《Probabilistic Robotics》（粒子滤波、占据网格、探索）
- Kaelbling, Littman, Cassandra（1998）POMDP
- Stone《Theory of Optimal Search》（贝叶斯搜索）

## 4. 对手建模

**我们用的**（sv）
- 逻辑层：对手最早几 Tick 能到。这相当于对手的**可达集**：每 Tick 至多走一格，从最后目击点向外扩张。
- 行为层：在真值上拟合的 9 个拿走率。

| 方法 | 要点 | 什么时候用 |
|---|---|---|
| 可达集 / 追逃博弈 | 被追者的可能位置随时间扩张，看见后收缩为一点 | 就是我们的逻辑层；在“警察与小偷”、追逃问题里系统研究过 |
| 粒子滤波跟踪对手 | 用一组样本表示对手可能的位置，按它的行为模型推进，看见或没看见时更新权重 | 比可达集多一层“它更可能往哪走” |
| 贝叶斯对手类型 | 先假设几种对手类型（贪心采集、好战、保守），按观察做后验 | 对手风格差异大、能观察足够多步时 |
| level-k / 认知层级 | 假设对手会推理 k 层（“它认为我会怎么做”） | 对手也在建模我们时 |
| 虚拟对局（fictitious play） | 对对手的历史动作频率做最优反应 | 重复对局中学习对手 |

**模型校准**是对手建模的关键一步，我们做了：
- 指标：对数损失、Brier 分数、可靠性图（预测 0.3 的事件实际发生的比例是不是 0.3）。
- 修正：Platt 缩放、保序回归（isotonic regression）。
- 验证：交叉验证要按地图分组，否则同一张图的信息会泄漏到测试集。

**延伸阅读**
- Albrecht & Stone（2018）《Autonomous agents modelling other agents: A comprehensive survey》
- Camerer, Ho, Chong（2004）认知层级
- Brown（1951）虚拟对局
- Guo 等（2017）《On calibration of modern neural networks》

## 5. 博弈论求解

**我们用的**：一对一局部对抗按**随机博弈**精确求解。每个状态是一个矩阵博弈，用线性规划求混合策略，在状态之间做 Shapley 值迭代。

| 方法 | 要点 | 什么时候用 |
|---|---|---|
| 矩阵博弈 + 线性规划 | 两人零和，一步同时行动，LP 求 maximin 混合策略 | 我们每个状态的子问题 |
| Shapley 值迭代 / minimax-Q | 随机博弈的动态规划版本，或它的强化学习版本 | 状态少、模型已知用前者；模型未知用后者 |
| 一般和与多人博弈 | 纳什均衡可能很多，max^n、paranoid 假设各有偏差 | 四队时；我们用“−⅓ × 对方伤害”把四队结构折进两人收益 |
| 反事实遗憾最小化（CFR） | 不完全信息博弈的主流解法，德州扑克 AI 的核心 | 隐藏信息多、需要混合策略防被针对时 |
| 遗憾匹配（regret matching） | CFR 的基本单元，简单的在线学习 | 重复博弈中逼近均衡 |
| Double Oracle / PSRO | 只在“有用的策略子集”上求均衡，逐步加入最优反应 | 策略空间大时；AlphaStar 联赛的理论基础 |

**为什么要混合策略、为什么用哈希抽样**：纯策略可以被对手预测和针对。同时行动的对峙里，确定性规则会让双方形成镜像。我们的 s7 等待和一对一查表都按 (Tick, 队伍) 的哈希抽样，就是这个原因。

**延伸阅读**
- Shapley（1953）随机博弈
- Littman（1994）minimax-Q
- Zinkevich 等（2007）CFR
- Sturtevant & Korf（2000）paranoid；Luckhardt & Irani（1986）max^n
- Lanctot 等（2017）PSRO
- Shoham & Leyton-Brown《Multiagent Systems》

## 6. 实时决策中的搜索

**我们用的**：路线用束搜索（宽 20、深 4），战术层每 Tick 对选项打分。

| 方法 | 要点 | 优缺点 |
|---|---|---|
| 束搜索 | 每层只保留最好的 k 个部分解 | 快、可控，但会剪掉开头看起来差的好序列 |
| Alpha-beta / expectimax | 轮流行动的博弈树；expectimax 处理随机节点 | 不适合同时行动和多人 |
| 蒙特卡洛树搜索（MCTS / UCT） | 随机模拟 + 置信上界选择，随时可停 | 通用性强，需要一个够快的模拟器 |
| 同时行动 MCTS（DUCT、SM-MCTS） | 每个节点上各方分别用 bandit 选动作 | 同时行动博弈的标准做法 |
| 信息集 MCTS（ISMCTS）/ 确定化 | 先按信念采样一个“完整世界”，在上面搜索，多次平均 | 部分可观测时；算法设计.md 9.2 规划过的方向 |
| 滚动时域进化（RHEA） | 用进化算法优化未来 N 步的动作序列，每步只执行第一个 | GVGAI 比赛里常胜，简单有效 |
| 随时可停（anytime）算法 | 给多少时间就算多少，超时就返回当前最好的解 | 0.5 s/Tick 的硬约束；我们靠算得快（中位 1.7 ms）绕开了这个问题 |

**一个常见的陷阱**：搜索会放大模型误差。模型越不准，搜得越深越会选中“模型里看起来好、实际上差”的计划。我们第一阶段的全局路线计划反而比局部规则差，就是这个原因。所以要先校准，再加深搜索。

**延伸阅读**
- Kocsis & Szepesvári（2006）UCT
- Browne 等（2012）《A survey of Monte Carlo tree search methods》
- Cowling, Powley, Whitehouse（2012）ISMCTS
- Lanctot 等（2014）同时行动 MCTS
- Perez 等（2013）滚动时域进化

## 7. 学习方法：强化学习与自我对弈

我们没有用学习方法：规则清楚、样本贵、比赛周期短，模型 + 搜索更划算。但它是这个领域的另一条主线，值得了解。

| 方法 | 要点 | 代表成果 |
|---|---|---|
| 价值 / 策略梯度强化学习（DQN、PPO） | 从对局奖励里学策略 | Atari；PPO 是很多比赛的基线 |
| 自我对弈 + 搜索 | 网络给搜索提供先验和估值，搜索结果再训练网络 | AlphaGo Zero、AlphaZero |
| 联赛训练（league） | 主力、专门针对主力的“剥削者”、历史版本一起训练，防止循环克制 | AlphaStar。我们的 thief 就是一个手写的剥削者 |
| 多人不完全信息 | 蓝图策略 + 实时搜索 | Pluribus（六人德州扑克） |
| 模仿学习 | 先模仿强对手或人类的对局，再强化 | 冷启动常用 |

**什么时候值得用**：规则复杂到写不出好模型、可以低成本跑大量对局、比赛周期长。Lux AI 和 Halite 的后期冠军里有学习方法，前期多是规则方法。

**延伸阅读**
- Sutton & Barto《Reinforcement Learning: An Introduction》
- Silver 等（2017、2018）AlphaGo Zero、AlphaZero
- Vinyals 等（2019）AlphaStar
- Brown & Sandholm（2019）Pluribus

## 8. 决策理论：探索与利用、边际价值

**我们用的**
- 一切换算成**终局期望得分的边际变化**，伤害价值在 8 个分位点上平均。
- 探索价值随时间衰减。

| 概念 | 要点 | 和我们的关系 |
|---|---|---|
| 期望效用、边际分析 | 只看“这一步让终局多多少”，封顶后的边际为 0 | 我们的“一个刻度”原则 |
| 信息价值（VOI） | 一条信息值多少 = 有它时的最优决策 − 没有它时的最优决策 | 可以用来决定“先去看一眼”值不值 |
| 多臂老虎机（UCB、汤普森采样） | 探索与利用的标准权衡 | 我们的探索 / 采集取舍是它的空间版本 |
| Gittins 指数 | 带折扣的老虎机的最优指数策略 | “先拿快消失的”这类时间价值排序的理论原型 |

**延伸阅读**
- Russell & Norvig《Artificial Intelligence: A Modern Approach》（决策理论、信息价值）
- Lattimore & Szepesvári《Bandit Algorithms》

## 9. 评测方法

我们花了大约一半的工作量在评测上。下面这些方法在国际象棋引擎开发、线上 A/B 测试里都是标准做法。

| 方法 | 要点 | 我们的对应 |
|---|---|---|
| 公共随机数（CRN） | 两个版本用同样的随机种子、地图、席位，比较差值，方差大幅下降 | 逐格配对 |
| A/A 测试、安慰剂 | 同一版本跑两次，看噪声有多大 | 安慰剂批次 |
| 检验力分析、最小可检测效应 | 事先算出要多少样本才能看出预期大小的差异 | mde = 2.8 SE |
| 序贯概率比检验（SPRT） | 边跑边判断，证据够了就停 | Stockfish 的 Fishtest 用它决定每个补丁是否合入 |
| Elo、Bradley–Terry、TrueSkill | 从两两或多人对局结果估计实力 | 多版本、多对手排名时 |
| 方差缩减（CUPED） | 用实验前的协变量减掉可预测的噪声 | 可以用“地图 × 席位”的历史成绩做协变量 |
| 方差分解 | 区分程序、地图、席位各占多少 | `variance.py`、赛制公平性.md |

**延伸阅读**
- Wald（1945）SPRT；Stockfish Fishtest 文档
- Herbrich, Minka, Graepel（2006）TrueSkill
- Kohavi, Tang, Xu《Trustworthy Online Controlled Experiments》
- Deng 等（2013）CUPED

## 10. 用 LLM 解析自然语言

**我们用的**：系统提示 + 只输出 JSON + 本地严格校验 + 相对时间由本地程序换算。

| 方法 | 要点 |
|---|---|
| 结构化输出 / JSON 模式 / 函数调用 | 让模型按给定的 schema 输出 |
| 约束解码 | 解码时只允许符合语法的下一个 token，输出必然合法 |
| 校验 + 有限重试 | 用 schema 校验，不合法就带着错误信息重试 |
| 把计算移出模型 | 模型只抽取原文里的数字，加减换算交给代码 |
| 提示注入防护 | 把输入明确标为数据，输出只接受白名单字段 |

## 11. 学习路线建议

1. **打基础**
   - 《Artificial Intelligence: A Modern Approach》：搜索、博弈、决策理论、POMDP。
   - 《Reinforcement Learning: An Introduction》：强化学习。
2. **按兴趣深入**
   - 博弈：《Multiagent Systems》→ CFR → PSRO。
   - 搜索：MCTS 综述 → ISMCTS → 同时行动 MCTS。
   - 运筹：定向越野综述 → LKH → ALNS。
   - 不确定性：《Probabilistic Robotics》。
3. **看比赛**：读 Ants、Halite、Lux AI 冠军的赛后总结，对照自己的做法。
4. **练评测**：读 Fishtest 的 SPRT 设置和《Trustworthy Online Controlled Experiments》。评测做对了，其他方向才分得清好坏。

## 12. 回头看：如果重做 RMTC，最值得试的三个方向

| 方向 | 为什么 | 前提 |
|---|---|---|
| 粒子滤波跟踪对手 + 确定化搜索（ISMCTS） | 在逻辑可达集的基础上再建模“对手更可能往哪走”，在采样出的完整世界上搜索资源顺序 | 一个够快的对手行为模型，且先在真值上校准 |
| 联赛式评测 | 主力、多个剥削者、历史版本组成对手池，防止只对某类对手有效 | 自动化批测（我们已有） |
| SPRT 序贯检验 | 每个改动跑到证据够了就停，省下大量对局 | 预先定好效应大小和错误率 |

上限仍然是 9.10 的结论：对 mi 的胜率从约 0.6 最多到约 0.7，所以这些方向更多是“学方法”，而不是“还有很多分可拿”。
