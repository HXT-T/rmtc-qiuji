# 赛制公平性：用对局数据检验比赛设计

问题：这个比赛能否可靠地选出更强的程序？哪些结果由程序决定，哪些由席位、地图和赛制决定？

数据来自本仓库的评测平台：53 批、1906 场第二阶段练习对局，练习裁判 `practice_v1.1`，250 ms/Tick。每条结论都标了证据强度。规则写明练习图不代表正式比赛地图（规则 §2.4），所以这里检验的是**赛制与设计方法**，不是对某场正式比赛的指控。

---

## 1. 方法

- **席位轮换设计**：每张地图上，被测程序依次坐 A、B、C、D 四个席位，另外三席是同一个程序（封存版 q1030）。每个席位得到的程序组合相同，所以席位之间第一率的差异只能来自席位本身（出生点、地图几何、结算顺序）。
- **检验**：各席位第一率与 0.25 比较，用 χ²(3)；p < 0.001 对应 χ² > 16.3。
- **拆分**：第一率差异再按得分项（资源、伤害、任务）拆开，区分“真实的得分不对称”和“排名机制的放大”。

## 2. 发现

| 2 | 0.27 | 0.20 | 0.21 | 0.33 | 7 |
| 3 | 0.13 | 0.33 | 0.11 | **0.43** | 46 |
| 4 | 0.25 | 0.30 | 0.18 | 0.27 | 5 |
| 5 | 0.22 | 0.31 | **0.46** | 0.01 | 66 |
| 6 | 0.29 | 0.08 | 0.36 | 0.26 | 28 |
| 7 | **0.52** | 0.14 | 0.08 | 0.25 | 71 |

每张练习图约 155 场。9 张练习图中有 6 张 p < 0.001。

### 2.2 偏差有两种不同的来源（强）

把第一率按得分项拆开，可以看出两种完全不同的机制：

| 图 | 席位 | 平均总分 | 资源 | 伤害 | 任务 |
|---|---|---|---|---|---|
| 1 | A / B / C / **D** | 39.3 / 38.9 / 31.4 / **45.3** | 47 / 47 / 35 / **71** | 923 / 800 / 504 / 804 | 2.9 / 3.0 / 2.2 / 2.9 |
| 5 | A / B / C / **D** | 39.8 / 42.3 / 43.0 / **29.2** | 48 / 60 / 62 / **29** | 760 / 651 / 895 / 421 | 3.0 / 3.0 / 3.0 / 2.0 |
| 7 | A / B / C / D | 38.3 / 36.2 / 36.6 / 38.1 | 51 / 49 / 49 / 51 | 705 / 482 / 652 / 589 | 2.8 / 2.9 / 2.9 / 2.8 |
| 9 | A / B / C / D | 40.7 / 40.5 / 40.6 / 40.1 | 50 / 50 / 50 / 50 | 971 / 834 / 861 / 715 | 3.0 / 3.0 / 3.0 / 3.0 |

**机制一：动态的资源不对称（图 1、5）。**
- 图 1 的 D 席平均拿 71 资源，C 席只拿 35；图 5 的 D 席只拿 29。
- 静态检查看不出来：图 1 上按“离哪个出生点最近”划分，四个席位的领地资源都是 50，到中心 (12,12) 都是 17 步。
- 差异来自对局的动态：谁先扫哪片区域、对手的路线经过谁的领地。静态几何对称不等于对局对称。

**机制二：赢者通吃的放大（图 7、9）。**
- 图 9 四个席位的平均总分相差不到 0.6 分（40.1–40.7），资源都是 50，任务都是 3.0；第一率却是 0.45 对 0.06。
- 原因是得分封顶：资源、任务都拿满，对抗分大多封顶（D ≥ 500），总分几乎相同。第一名由同分规则里不封顶的有效伤害决定。
- 一个席位只要系统地多遇到几次交战，就能把几乎为零的期望分差变成 7 倍的第一率差距。

**含义**：平衡检验不能只看地图几何，也不能只看平均分，要用模拟对局看**排名**（第 3 节的“受限对局”方法正是这样做的）。

### 2.3 偶数尺寸地图上的单格目标天然不对称（强）

- 24×24 地图的旋转中心在 (11.5, 11.5)，没有正中心格。任务坐标 [12,12] 和堡垒 (11,11)–(13,13) 都偏向右下。
- 33 张完全旋转对称的随机图上，各席位到 (12,12) 的平均路程：C 12.2、B 12.9、D 13.1、A 13.8。第一率：C 0.32，A 0.22（n = 498，约 3.5 倍标准误）。
- 只要地图是偶数尺寸、目标只占一格，这种偏差就消除不了。

### 2.4 单场定胜负，赛制的识别力很低（强）

- 规则（§3）：每轮每组 4 队打 **1 场**，前两名留在胜者组，其余进败者组或淘汰；总决赛也是 1 场。
- 本仓库最强的程序面对一群更弱的对手（第一率 0.46、与每个对手比总分胜 66%），单场进前两名的概率只有 0.69，单场拿第一的概率不到一半。
- 作为对照：我们用 100 场才把第一率估到 ±0.05。每轮 1 场只能区分差距很大的程序。
- 双败淘汰给了每队两条命，缓解了一部分噪声，但每一轮本身仍是一次单场抽样，再加上 2.1 的席位偏差。

### 2.5 第一阶段结果依赖参赛设备（机理强，影响大小未测）

- 规则：动作窗口关闭后不再接收，迟到的动作不补执行（§5.1）；第一阶段 100 ms/Tick，各队使用自己的设备接入。
- 实测（练习裁判，100 ms/Tick）：86 ms 完成的决策被执行，112 ms 的被丢弃；同一版本重跑，第一率差 −0.09 ± 0.04。
- 所以同一程序在慢电脑上会丢动作。计算量大的算法、解释型语言（规则推荐 C++，但允许任何语言）系统性吃亏。第一阶段又决定第二阶段的种子。

### 2.6 封顶与零和压缩了区分度（中）

- 对抗分在 74%–81% 的对局里已经封顶，之后伤害只影响同分比较。
- 资源每场 200 全部被四队拿光，是零和的。一个程序的打法会改变另外两队谁赢（多人博弈中的“造王”问题），而同组对手是谁并不由程序决定。

### 2.7 做得好的地方

- 战斗没有随机命中、暴击，相同配置和动作结果可复现（§1）；
- 所有队伍参数、AI 服务统一，并提供公开测试裁判；
- 同分规则明确到小数点后九位，加赛时轮换席位；
- 规则明确不按席位字母决定名次。

## 3. 相关研究

- **用受限的 AI 对局评估平衡**：Jaffe 等人（AIIDE 2012）提出让受限策略的智能体与正常智能体对局，用胜率差来量化平衡，以替代反复人工试玩。第 2.2 节的结论（几何对称不等于对局对称）正是这种方法要解决的问题。[论文](https://ojs.aaai.org/index.php/AIIDE/article/view/12513)；作者的博士论文 [Understanding Game Balance with Quantitative Methods](https://digital.lib.washington.edu/researchworks/handle/1773/22797) 进一步把平衡问题归结为“受限玩家之间的公平性”。
- **赛制能否选出最强者**：Ryvkin 与 Ortmann（Management Science, 2008）比较了单场竞赛、淘汰赛和循环赛的“预测力”，即选出最强选手的概率，并分析了它如何随选手数量与噪声水平变化，有时并不单调。[论文](https://pubsonline.informs.org/doi/fpi/10.1287/mnsc.1070.0856)。本比赛每轮单场、噪声大（2.4 节），正落在这类分析关心的区域。
- **多人对局的实力评估**：TrueSkill（Herbrich、Minka、Graepel，NIPS 2006）把 Elo 推广到多人、多队，并显式建模不确定性，需要的是大量对局，而不是一场定胜负。[论文](https://papers.nips.cc/paper_files/paper/2006/file/f44ee263952e65b3610b8ba51229d1f9-Paper.pdf)。
- **位置优势的经验数据**（社区统计，非同行评审，受玩家水平与匹配方式影响）：
  - 国际象棋先手胜率常被引为 52%–55%；
  - Dominion 高水平双人对局先手约 58.8%；
  - 四人 Commander 一号位约 29.2%（公平值 25%）。

  对照之下，本比赛练习图 1 的 D 席 80%，偏差比这些成熟游戏大一个数量级。[Commander 席位数据](https://playgroup.gg/commander/turn-order)、[First player advantage（博客汇总）](https://freethoughtblogs.com/atrivialknot/2019/07/28/first-player-advantage)。

## 4. 建议

| 问题 | 建议 |
|---|---|
| 席位偏差（2.1–2.2） | 每组按 4 个席位轮换打 4 场，取总分；发布前用模拟对局（而非几何检查）做席位平衡检验，并公布结果 |
| 偶数地图的单格目标（2.3） | 使用奇数尺寸地图，或把目标换成关于旋转中心对称的 2×2 / 多格区域 |
| 单场噪声（2.4） | 每轮多场，或积分循环赛加评级；至少让决赛多打几场 |
| 设备依赖（2.5） | 第一阶段由裁判机统一运行参赛程序，或放宽 Tick 时限并公布参考硬件 |
| 封顶与零和（2.6） | 同分比较之前加入更有区分度的项，或降低“满分即止”的项的比重 |

## 5. 局限

- 练习图不等于正式地图；结论是对设计方法的检验。
- 对手只有 q1030 一种，被测程序在 53 批里版本不同。席位效应的估计在轮换设计下不受这一点的偏置，但效应大小可能随程序风格变化。
- 没有在正式比赛设备与 500 ms/Tick 下测设备依赖的影响大小。
