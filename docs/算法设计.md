# 算法设计说明

**总原则：一切服务于不断突破上限的、最全面的算法程序，不惜一切手段；唯一的约束是保持代码简洁。**
重计算、离线预计算、搜索、学习方法都可用。评测、exploiter、文档都是手段：找到弱点、建模解决，再找下一个上限。

维护约定：本文件是 rmtc-qiuji 唯一的设计文档，按“总 → 分”组织：第 0 节一页看完现状，后面各节是依据。
- 任何算法改动先在第 6 节写成方案，再实现；采用的写进第 7 节，否定的在第 4、5 节留一行结论和证据，代码删除。
- 证据只引用可复现的实验（第 3 节），每条结论标强度：**强** = 确定性实验或 ≥ 2 个标准误且有对照；**中** = 方向一致但只有约 2 个标准误；**弱** = 有迹象，检验力不足。
- 不再有用的内容直接删掉（历史在 git 里）。

## 0. 总览

**当前最佳 = v8 + 后期等待（s7）**，未提交（基于 freeze-1030 = 059875d）。

| | 现状 | 上限 / 参照 |
|---|---|---|
| 第一阶段 | 在线 96.98% × 精确最优（401 张图） | 全知 99.55%；只告知资源位置 98.31% |
| 第二阶段 | 对 3 个 q1030，第一率约 0.45–0.5（同实力为 0.25）；固定 36 格 s7 0.61、v8 0.56（含 v8 的选择好运，见 3.3），随机 32 格 0.47 / 0.44 | — |

**第二阶段的分数在哪里决定**（v8，固定 36 格）：
- 输局与最强对手的差距：资源 −7.3 分、任务 −2.5、伤害 −0.9。**资源是绝对的大头**，多数胜负只差一个普通资源。
- 伤害只在两类局里有用：我方伤害不到 500 的局（14/36），以及与最强对手同分、按不封顶伤害分胜负的局（10/36）。
- 任务很少丢（36 格里 3 场缺高价值任务，都是座位决定的）。

**接下来最值得做的**（理由见第 5 节）：
1. **第二阶段路线的目标函数重写成“剩余比赛的期望得分”**（6.1）。资源取舍是大头，而现在的收益/时间比、sigmoid 悲观、探索价值、全额任务加成是一起调出来的平衡，逐项“改准”已经四次失败。
2. **战术层多 Tick 前瞻**（6.2）：单 Tick 模型无法一致地给“对攻”计价。
3. **后期交战作为路线目标统一计价**（6.3）：让“资源没了就转去打”由同一个刻度自动完成。
4. 第一阶段暂停：剩余差距要靠校准过的信念加多步搜索，代价大且有对生成器过拟合的风险。

## 1. 规则与得分结构（规则 v1.2）

| | 第一阶段 | 第二阶段 |
|---|---|---|
| 地图 / 时长 | 20×20，100 Tick × 100 ms，单车 | 24×24，500 Tick × 500 ms，四队 |
| 动作 | MOVE / WAIT | MOVE / ATTACK / DEFEND / WAIT |
| 得分 | 40·R/200 | 30·min(R/120,1) + 15·min(D/500,1) + 5·任务数 |
| 其他 | 9×9 视野 | 攻击 20（被防御 10），同行/同列 1–2 格，障碍不挡；每死一次 D −60，击杀奖励 60 由攻击者平分 |

对设计有直接影响的几条：
- **同分顺序**：任务数 → 资源总值 → 不封顶有效伤害 → 无效动作。
- **封顶**：资源很少到 120，基本全值；伤害多数局远超 500，超过之后只剩同分比较的用处。
- **规则 5.2 的结算顺序**：先按移动前的位置结算攻击，再移动；本 Tick 走进射程不会挨打，所以没有“预判出手”。不能互换位置，多车争一格全部失败。
- 帧里只有本队得分，看不到其他队得分；任务分须至少一次真实 AI 成功调用；事件公告须由 LLM 理解（禁止正则）；地图真值不得作为参赛输入。

## 2. 当前算法

```text
感知 ─► protocol.Frame ─► planner.WorldMemory（只记本队合法感知）
公告 ─► ai.AIWorker（后台线程）─► events.validate_plan ─► EventBook
                         ▼
策略层  planner.route：Dijkstra 距离 + 目标选择（第一阶段：精确 DP / 巡回 / 束搜索；第二阶段：束搜索 + 兜底链）
                         ▼
战术层  engine._choose：第二阶段本 Tick 对 攻击 / 防御 / 移动 / 等待 打分取最高 ─► 动作（第一阶段直接按路线走）
```

**共用**
- 距离：Dijkstra，未知格当作可走、代价 +0.15；按地形缓存。
- 未见区资源后验：每个未见格的期望价值 = (公布总值 − 本场已见总值) / 未见格数（`explore_value`）。
- 探索目标：前沿格按“新见格数 / (代价 + 2.5)^0.85”取前 2 个。

**第一阶段**（单车，资源只会被自己拿走，已见资源不打折）
1. 16 个资源都已见过、剩余 ≤ 12 个：精确状态压缩 DP（`known_map.solve`），剩余集合变化时才重算。
2. 否则走“最近优先 + 2-opt”的巡回（已知资源 + 2 个探索点），装得下就用。去掉它每图 −10.2 ± 0.9（2026-11-04 复核），是主力。
3. 装不下时用束搜索。
4. 探索价值按 1 − t/100 衰减（越晚发现越来不及收）。

**第二阶段：目标与束搜索**
- 目标：
  - 已见资源：收益 × 陈旧（每 Tick −0.006，下限 0.45）× 可见对手竞速（0.45）× 到达时存活 × 紧迫（1.45）。
  - 到达任务：5.5。
  - 事件点。
  - 2 个探索前沿：价值按领地加权，到第 150 Tick 线性衰减到 0。
  - 资源带来的任务进度另加全额任务加成。
- 存活（`_survival`）：假想对手出生点 = 本队出生点绕中心的旋转。资源 p 到 t 时刻仍在的概率是 Π_j(1 − σ((t − t_j)/3))，并以“上次看见时还在”为条件。探索的领地权重用同一模型。
- 束搜索：宽 20、深 4，效率 = 累计收益 / (到达 + 3.5)^0.78，深度折扣 0.91^depth。

**第二阶段：随比赛进程的切换**（没有显式的阶段开关，靠价值随时间变化自然过渡）
1. 开局到约第 60 Tick：资源和探索的价值高，束搜索几乎总有目标。开局去中心的到达任务也在这里完成。
2. 资源被拿完、探索价值到第 150 Tick 衰减到 0 之后，束搜索没有正收益的目标，路线依次退到兜底链：
   - **交战**：走到能打到某个可见对手的格子；我方伤害未到 500 时，对手正走过来对齐就原地等它，即 s7，见 6.3 与第 7 节。
   - **调查**：去 30 Tick 内的目击点。
   - **兜底前沿**。
   - **巡逻**：去最久没看过的地方。
3. 战术层随之换权重：已知资源和任务都没了以后，同分权重 0.009 → 0.05。伤害一直按终局计价（`scoring.damage_value`：预测本场终局伤害，在 8 个分位点上平均“这次伤害让封顶后的终局分变了多少”）。所以伤害已远超 500 时，打架本身不再值分。
4. 不足（数据见第 4 节）：
   - 交战只在束搜索**完全没有**目标时才启用，一个价值约 0 的残余目标就能挡住它（m9_r2 在 40 HP 的对手旁等了 43 Tick）。
   - 交战只对视野内的对手，后期伤害受“遇不遇得到对手”限制，而不是受“愿不愿意打”限制（agg 探针）。
   - “后面时间充足就多打”并不总对：22/36 局伤害已封顶，多打只影响同分，还会给没封顶的对手送分（s6）。
   - 正确的做法是把交战和其他目标放到同一个“终局领先”刻度上（6.3），而不是加一个按时间的开关。

**第二阶段：战术层**（`engine._choose`）
- 最简单的情形先查精确解（`engine._duel`，d3）：资源、探索、任务都完，视野里恰好一个对手在 4 步内，双方都不在保护中，无已知事件，两车周围 1 格是空地。
  表由 `eval/duel.py` 解出（同时行动矩阵博弈，收益 = 我方伤害变化 − 1/3 · 对方伤害变化，取 maximin），混合策略按 (Tick, 队伍) 哈希抽取。见 6.2。
- 其他情形：选项为等待、防御、各方向攻击、各方向移动。
- 沿路线移动得路线效用（夹在 0.35–3.5），离开路线 −0.25 + 0.15×进度。
- 生存损失 = 期望受伤 × 生存权重（balanced 0.07）。本 Tick 期望受伤 ≥ HP 时，另加死亡代价（5.0 + 阵亡扣分的终局价值）。
- 伤害与击杀奖励按终局计价。
- 事件机制（爆炸、分裂、反射、易伤、堡垒、辣椒）各自在对应选项里计入。

**没有推导的常数**（经验值，是 6.1 要消掉的对象）：
- 路线：效率指数 0.78 与 +3.5、0.91^depth、陈旧 0.006/Tick（下限 0.45）、竞速 0.45、紧迫 1.45、到达任务 5.5、未知格代价 0.15、前沿 (cost+2.5)^0.85 取前 2 个、兜底前沿 ×0.15 与重访 0.4、sigmoid 尺度 3、探索到第 150 Tick 衰减。
- 战术层：路线效用 0.35–3.5、离开路线 −0.25 + 0.15×进度、生存权重 0.07/0.10/0.035/0.18、防御概率 0.85/0.5 与 0.75/0.2、同分权重 0.05/0.009、未来风险 0.45、死亡时间代价 5.0。

## 3. 评测方法与陷阱

### 3.1 评测集与指标
- **第二阶段**：
  - 地图与阵容：`eval/maps/stage2_1..9.json`，截图提取，各 12 普通 + 4 高价值，任务为两个普通、一个高价值、到达 [12,12]，事件关闭。每张图 4 个席位轮换，共 36 格；阵容为被测版本 + 3 个 q1030（freeze-1030，永久保底对手）。
  - 没见过的地图：`eval/maps.py` 随机图，四重旋转对称，用 `--maps r1001,...` 固定种子做配对。
  - 指标：主指标第一率，次指标领先分（本队得分 − 其他队最高分）。资源、伤害、任务只用于诊断。
- **第一阶段**：练习图 + 400 张宽分布随机图，`eval/stage1.py bench`，结果确定无噪声，与精确最优比。`--reveal terrain,resources` 做上限分解。两个版本约 1 分钟，配对标准误约 0.2–0.6 / 图。
- 命令与工具见 `eval/README.md`：
  - `batch.py`：批测。
  - `paired.py`：逐格配对。
  - `play.py`：看一场，桌面“RMTC 第二阶段对局.bat”调用它。
  - `headroom.py`、`pickups.py`：资源诊断。
  - `exploiters.py`：thief。
  - `regret.py`：第一阶段每步后悔值。

### 3.2 配对与检验力
- 对局是确定性的，与机器负载无关：v8 在重负载下重跑 36 格，33 格逐格相同，没有胜负翻转。所以两个批次的差别来自程序。
- 任何改动都会通过蝴蝶效应改变约 1/3 的格子，单看胜负格数不可靠。要逐格配对，报告差值 ± 标准误，超过 2 个标准误才算有效。
- 36 格时第一率差的标准误约 0.04–0.07，领先分约 0.4–1.0。预期效应小于 0.1 时，必须同时看机制指标（例如对峙 Tick、封顶拆分）。

### 3.3 已知陷阱
- **选择好运（强）**：v8 是从 v6–v8 里因为在这 36 格上最好才被选中的，所以它在这 36 格上偏高约 0.1 第一率、1.5–2 资源。
  - 证据：三个中性安慰剂（每个目标格固定 ±1% 偏好）对 v8 第一 −0.08 ～ −0.11，共 10 个翻转全是由胜转负。
  - 对策：改动开局的变体，对照用若干安慰剂批次的逐格均值（`paired.py` 给多个基线）。
  - 例外：**只改后期的变体**开局与 v8 完全相同，会继承这份好运，所以要与 v8 本身配对；这时 v8 后期的好运只会压低候选，估计偏保守。
- **练习裁判默认 100 ms/Tick**：决策 ≥ 60 ms 的动作会迟到不执行（规则 5.2）。凡是增加计算量的变体，都要检查没走成的移动，或用 `--tick-ms 250` 复测。全知 oracle 的第一次测试就因此无效。
- **批次不是完全确定的（强）**：同一份代码重跑，约 1/10 的格在第 11–17 Tick 就分叉（计时差异），之后整局不同，资源可差 30。
  只改后期的变体，凡是在它第一次生效之前就分叉的格都是噪声。对策：按“第一次分叉的 Tick 是否早于变体第一次生效”拆开，
  只在变体造成分叉的格上估计效果（`paired.py --cause 理由`，读 bot 日志的 decision 记录）。d1 的 −0.11 里有一部分就是这种噪声。
- **安慰剂不能逐 Tick 变化**：逐 Tick 抖动会新增摇摆，本身就有害。
- **并行**：两批同时跑要给不重叠的 `--first-slot`，合计并行不超过 6。在 Windows 侧停掉 `wsl.exe` 不会停掉 WSL 里的裁判和程序，要按 `runs/<批次>` 杀进程（含 ppid 1 的 referee_node）。
- **检验力不足时，“没测出效果”不等于“没有效果”**。早期 20 格的检验追过噪声（2026-11-03 v2–v4）。

### 3.4 上限分解（极致 = 每一步按已知信息最大化终局期望）
差距分三部分测：
- 搜索：全知时离精确最优还差多少。
- 信念：预测与实际是否校准。
- 信息上限：不限时间的强在线算法也拿不回的部分。

只在测出来的大头上投入。

## 5. 反思：改进方向为什么没效果——策略本身的问题还是设计的问题

每个被否定的方向按根因分四类。判断依据：机制指标是否按预期变化（实现对不对），以及失败能否由一个可指认的结构缺陷解释（设计对不对）。

| 方向 | 结果 | 根因 | 依据 |

**结论**
1. **失败最多的是“设计”类，不是方向错。** 最典型的是第二阶段路线：v8 的几个经验项（sigmoid 悲观、效率指数 0.78、探索价值、全额任务加成）在当前对手池里互相抵消出了一个好平衡。每次只把其中一项改“对”，都会打破平衡。所以问题在目标函数本身没有从“终局期望得分”推导出来，而不在“信念要准”这个方向。正确的做法是一次重写目标函数（6.1），而不是继续逐项修。
2. **单 Tick 战术模型是第二个结构瓶颈**：凡是需要“几 Tick 后的结果”的改动（s1、s3 设想），都只能加在部分选项上，必然不一致（6.2）。
3. **真正“策略本身错”的方向，都在动手前量化一下就能排除**（碰撞、折返、地形、对手巡回）。今后先量化上限，再实现（第 0 原则不变）。
4. **方法类错误都已有对策**：安慰剂基线、后期变体与对照配对、tick 时长检查、确定性复现。

## 6. 待做方案（都未实现，实现前再细化）

### 6.1 第二阶段路线目标函数：剩余比赛的期望领先
**问题**：束搜索的效率 Σ收益/(到达+3.5)^0.78 只是“单位时间收益”的经验近似；存活用的 sigmoid 预测偏悲观约一个数量级；探索价值、任务加成又各自补偿。四次单项改准都失败（第 5 节）。

**模型**：
- 路线价值 = Σ P(到达时仍在 | 我们去追)·分值 − 机会成本 × 用时。
- 存活用校准好的追逐模型 H：Π_j exp(−λ(T − max(上次看见, t_j))⁺)，λ ≈ 0.008/对手。
- 机会成本 = 剩余比赛里单位时间还能拿到的期望分值，由未见区后验和已知资源算出，随资源枯竭下降。
- 任务进度、探索揭示的期望价值都在同一个“终局得分”刻度上计。
- 去掉 0.78、+3.5、0.91^depth、紧迫 1.45 等常数。

**验证**：
- 先离线：在 v8 的感知上重放，看路线选择的变化是否集中在争夺区。
- 再做 36 格对安慰剂基线，加随机图。资源应上升。
- 失败时检查是哪一项没校准，不回退到逐项修。

### 6.2 战术层：从最简单的情形做到精确最优，再逐步扩展
**最简单的情形**：1 对 1、空地、无事件。这是一个小的同时行动零和博弈（`eval/duel.py`）：
- 状态：对手相对位置（6 步内）+ 双方 HP。
- 每 Tick 一个矩阵博弈：等待、防御、攻击（在线上时）、4 个移动；规则 5.2 的结算与争格。
- 收益：我方有效伤害 − 对方有效伤害，击杀 ±120；之后每 Tick 折扣 0.97。
- 求解：HP 只降不升，按 HP 从低到高逐对做 Shapley 值迭代，每个矩阵博弈用线性规划求 maximin。8400 个状态，37 秒。

**量化**（s7 的 36 格，`scratchpad/duelgap.py`）：
- 干净的 1 对 1（一个对手在 6 步内、其他 ≥ 7 步、都不在保护中）每场 167 Tick，约占全场三分之一。
- 空地上我方实际动作比精确解每场少 93 期望相对伤害；q1030 少 48。
- 损失几乎全部来自“HP 比对手低”：在线上还手而不是离线（32），不在线上时往对手能对齐的位置走而不是保持距离（42）。
  这正是“开打时 HP 低、1 对 1 输掉”的那 3.2 次阵亡/场。s1 只给攻击选项加了代价，而精确解对所有选项一致计价。
- 精确策略多数是纯策略（4000 个 6 步内状态里只有 340 个要混合），但写不成短规则：最自然的手写规则在 636 个状态上不够好，
  例如必死时先打出伤害比逃跑好。所以直接用精确解，作为 `eval/duel.py` 生成的数据（`rmtc_bot/duel.json`），代码只是查表。

**第一步（d1）**：只在最简单的情形用精确解，其他情形不变。条件全部满足才查表：

- 双方周围 1 格内没有障碍和地图边界（空地，表的移动模型成立）。

混合策略按 (Tick, 队伍) 哈希抽取。开局不变，所以与 s7 逐格配对。

### 6.3 后期交战进束搜索，与其他目标同一刻度
**问题**：交战只在束搜索完全没有目标时才启用；价值约 0 的残余目标会挡住它。“资源没了就打”靠兜底链的顺序实现，不是比较出来的。

**模型**：
- 把“与可见对手 j 交战”作为束搜索目标，价值 = 一场对等交换对终局领先的期望变化（`damage_value`，含封顶与阵亡）。
- 我方伤害已封顶时，交换只剩同分价值，并要扣掉对手可能得到的分。
- 这样资源阶段它自然排在后面，资源没了自然排到前面，不需要按 Tick 的开关。s7 的“未封顶才等待”是它的特例。

**验证**：与当前最佳逐格配对（只改后期，所以不用安慰剂基线）；后期出手 Tick、伤害未封顶局的领先应上升。

### 6.4 第一阶段：校准信念 + 多步搜索（暂停）
资源成簇、墙成片的补全分布要先校准：估值与实际终值的均值一致、随时间稳定。然后在补全地图上做多步搜索，并用宽分布生成器检查是否过拟合。
