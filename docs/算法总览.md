# 算法总览

本文按模块介绍最终版本 **k3**（`main`）实际用到的全部算法，以及评测平台里的分析算法。每个算法都给出做什么、怎么做、为什么这样做，以及代码位置。设计的来龙去脉、证据和被否定的方向见 [算法设计.md](算法设计.md)。

---

## 0. 一页概览

**问题**
- 第二阶段四车同场，24×24 地图，500 Tick，视野 9×9。
- 得分 = 30·min(R/120, 1) + 15·min(D/500, 1) + 5·任务数。
- 资源每场共 200，零和，被拿光即止（中位第 68 Tick）。
- 伤害分和任务分双方基本都能拿满，**名次由资源决定**。

**整体结构**：四层，每 Tick 自上而下走一遍。中位耗时 1.7 ms，最长约 20 ms。

```text
感知帧 ─► 记忆（WorldMemory）       只记本队合法感知：地形、资源、对手目击
公告  ─► LLM 解析 ─► 校验 ─► 事件簿   自然语言事件 → 结构化事件
           ▼
世界模型   距离 · 未见区后验 · 资源存活（逻辑界 + 实测率）· 任务边际 · 伤害终局价值
           ▼
规划层     这几十个 Tick 去哪：在目标集合上做束搜索，输出下一步方向和“每步值多少分”
           ▼
战术层     这个 Tick 怎么动：最简单的一对一查精确解表，其余对等待 / 防御 / 攻击 / 移动打分
```

两层的分工：
- 规划层处理慢变量（资源、任务）。
- 战术层处理快变量（攻防）。
- 两层通过“沿路线前进一步值多少分”这一个数连接。

| 模块 | 核心算法 | 代码 |
|---|---|---|
| 记忆 | 视野累积、障碍可撤销、对手最后目击 | `planner.WorldMemory` |
| 距离 | Dijkstra（未知格可走加小代价），按地形缓存 | `Planner.distances` |
| 探索 | 未见区资源后验 × 领地权重，二维前缀和计数 | `explore_value`、`_territory`、`_unseen_counter` |
| 资源存活 | 对手最早到达的逻辑界 + 9 个实测拿走率 | `_arrivals`、`_keep`、`TAKE`、`KNOWN` |
| 路线 | 束搜索（宽 20、深 4），加兜底链 | `Planner.route` |
| 伤害价值 | 终局分位点平均的边际得分 | `scoring.damage_value` |
| 战术 | 选项打分；阵亡按独立攻击的概率分布计价 | `Engine._choose` |
| 一对一 | 同时行动随机博弈的精确解（Shapley 迭代 + 线性规划）查表 | `eval/duel.py` → `duel.json`、`Engine._duel` |
| 事件 | LLM 结构化抽取 + 严格校验 + 规则化效果 | `ai.py`、`events.py` |
| 第一阶段 | 状态压缩 DP 精确解；最近优先 + 2-opt 巡回；束搜索兜底 | `known_map.solve`、`Planner.route` |

## 1. 感知与记忆（`planner.WorldMemory`）

**原则**：看得见的事实是硬约束，先验只填补看不见的部分。程序只用本队合法感知，地图真值不得作为输入。

- **地形**
  - 视野里出现的格记入 `seen`，障碍记入 `obstacles`。
  - 视野里不再出现的障碍会被撤销：“世界分裂”事件的墙是临时的，事件结束后需要重新看到才认定它还是墙。
- **资源**
  - 视野里的资源记下位置、价值、最后看见的 Tick。
  - 视野里消失的资源立刻删除。
  - `ever_seen` 记录本场见过的全部资源，用于未见区后验。
- **任务计数**：只有在上一 Tick 站的格子上记着资源、且得分增量恰好等于它的价值时，才计为收集了一个该类资源。这样不会把别的加分误记成收集。
- **对手**
  - `enemy_sightings` 保存 30 Tick 内的目击，供“调查”使用；目击点在视野里却看不到人时删除。
  - `last_sighting` 保存每个对手整场的最后目击，供资源存活模型使用。
- **移动失败**：回执报告移动被挡（`E_BLOCKED`）时，那一格在 2 Tick 内不再作为第一步。被占或临时阻挡不是永久障碍。
- **协议健壮性**（`Engine.step`）
  - 同一 Tick 重发时返回缓存的动作，不会让状态前进两次。
  - 旧场次的帧直接丢弃。
  - 地图尺寸在场内变化时拒绝这一帧。
  - 用移动回执里的实际方向判断自己是否处于“幻术”反向状态。

## 2. 世界模型

### 2.1 距离：Dijkstra（`Planner.distances`）

- 四邻接，每步代价 1，另加以下修正：
  - 未见过的格当作可走，+0.15。地形全知只值 +0.29 分/图，不值得更复杂的模型。
  - 机器人所在格 +5。只有紧邻的下一步把机器人当墙（F-d）：下一 Tick 它多半已经走开。
  - 已知爆炸、分裂事件按“到达那一格的时刻”计入危险或阻挡。
- **缓存**：没有限时事件时，距离图只取决于记忆中的地形，按 (障碍集, 已见格数, 失败格) 缓存。
- **用途**：我们到各格、各目标两两之间、对手到各格的距离都用它。全程绕墙算真实步数，不用直线距离。

### 2.2 未见区资源后验（`explore_value`）

- 每个未见格的期望价值 = (公布总值 200 − 本场已见总值) / 未见格数。
- 价值按 0.25 分/资源值折算，并到第 150 Tick 线性衰减到 0：对手会把资源池拿空。
- 第一阶段只有自己一辆车，改为到比赛结束才衰减到 0。
- **探索前沿**
  - 前沿格的收益 = 站在那里能新看到的未见格（按领地权重加权）× 每格期望价值。
  - 按 收益 / (代价 + 2.5)^0.85 取前 2 个作为目标。
  - 视野窗口内的计数用二维前缀和，每格查询 O(1)。

### 2.3 领地权重（`_territory`、`_clear`）

- 假想对手出生点 = 我方出生点绕地图中心的旋转像：方图取 90°、180°、270°，非方图取 180°。
- 每个假想对手从第 0 Tick 起向外扫。某格在我们到达时仍未被扫过的概率 = Π_j (1 − σ((t_j − t)/3))，t_j 是对手 j 到这一格的步数。
- 这个权重只用于给“未见区值多少”加权（离对手近的未见区多半已被拿空），不用于判断已见资源是否还在。

### 2.4 资源存活：逻辑界 + 实测率（sv，`_arrivals`、`_keep`）

这是收益最大的一个模型：混合池第一率 +0.18 ± 0.05，资源 +5.1 ± 1.3，证据强。它回答的问题是：我们走过去时，这颗资源还在不在。

**逻辑层**：每个对手最早第几 Tick 能站上这一格。

| 我们对它的了解 | 最早到达 |
|---|---|
| 此刻看得见 | 它到这一格的真实路径步数 |
| 见过 | 从最后目击点算的步数 − 此后经过的 Tick（每 Tick 至多走一格），再与“阵亡后从出生点重来”的界取小 |
| 没见过 | 最近的假想出生点的步数 − 当前 Tick − 2（像与真实出生点可能差一格） |

最早到达晚于我们的对手，**绝不可能**先拿到。这一层是纯逻辑，没有参数。离线检验：判为“没有对手能先到”的 959 个样本，实际丢失 0 次。

**行为层**：能先到的对手实际拿走的概率。这是唯一从数据估计的部分。
- 按“了解程度”（看得见 / 见过 / 没见过）×“余量”（我们到达 − 它最早到达，分 < 3、< 8、更多）分成 9 格，在裁判真值上做最大似然估计（300 场，8315 个样本）：

  | | 余量 < 3 | < 8 | 更多 |
  |---|---|---|---|
  | 看得见 | 0.231 | 0.326 | 0.393 |
  | 见过 | 0.004 | 0.007 | 0.128 |
  | 没见过 | 0.002 | 0.024 | 0.052 |

- **对手视野里的资源**（F-a）：如果在我们看见对手的位置上，这颗资源在它的视野里，就改用 `KNOWN = (0.509, 0.575, 0.645)`。依据是实测：对手视野内的资源，被它在“步数 + 2 Tick”内拿走的比例为 0.51。
- **合并**：存活 = Π_j (1 − r_j)，只对能先到的对手 j 连乘。

**模型比较**：交叉验证对数损失 0.34，常数模型为 0.43，旧的扫掠模型为 3.78。旧模型的问题是把三个假想对手的到达连乘，地图中部的资源一律被判为“没了”，悲观了一个数量级。

**另外两个修正**
- 陈旧度：资源看见后每过一个 Tick 打 0.6% 的折扣，最低 0.45。
- 险胜竞速：我们比看得见的对手只快 0–4 步时，紧迫度 ×1.45，先去抢。

### 2.5 任务的边际价值（`_mission_bonus`）

- **收集 N 个某类资源**：剩余可得的同类资源不超过还差的个数时，每个记 5 / 还差个数。只有在“这颗不拿就完不成”时，它才带任务加成。
- **资源总值任务**：按这颗资源填补差额的比例记 5 × 填补 / 差额。
- **到达任务**：记 5.5，并放到资源之后做（k3，见 3.2）。

### 2.6 伤害的终局价值（`scoring.damage_value`）

- 一次伤害（或一次阵亡）现在值多少分，要看它改变了**终局**的封顶得分多少。
- **预测终局伤害**：本场速率向先验收缩（权重相当于 100 Tick）× 剩余 Tick；不确定度 = 一次攻击 + 30% 的速率误差。
- 在标准正态的 8 个等概率分位点上，平均“终局分的变化”。
- 结果是：伤害远超 500 时，打架本身不再值分，只剩同分决胜的一个小权重（0.009；资源和任务都完成后为 0.05）。
- 阵亡按 −60 伤害、在击杀奖励之后结算，与规则的结算顺序一致。

## 3. 规划层：去哪（`Planner.route`）

### 3.1 预警撤离

- 已公告、尚未生效的爆炸区或分裂线如果覆盖我们所在的位置，就找最近的安全格。
- 时间余量不超过 2 Tick 时立即撤离。

### 3.2 目标集合

| 目标 | 收益 |
|---|---|
| 已见资源 | 0.25 × 价值（超过封顶部分只计 0.012）× 陈旧度 × 到达时存活 × 紧迫度，加任务边际 |
| 事件点 | 天使回血（HP < 85）、堡垒中心（停留够时间后获得强化攻击） |
| 探索前沿 | 2 个，按 2.2 |
| 到达任务 | 5.5；**只在候选里没有资源和探索目标时**，或剩余时间不到走过去所需的两倍时才列入（k3） |

k3 规则的道理：资源会被对手拿走，越晚越可能没了；到达任务谁也拿不走，第 500 Tick 前什么时候完成都一样。所以资源期专程去做任务，是拿会贬值的收益换不会贬值的收益。路过那一格时，任务照样完成。满局抽查 16 场，任务完成数不降。

候选按 初始收益 / (步数 + 2) 截取前 20 个。

### 3.3 束搜索

- **状态**：(已访问集合, 当前位置, 累计收益, 用时, 第一个目标)。宽 20，深 4。
- **扩展**：每层把下一个目标加入序列。资源的存活按序列中**真实的到达时刻**计算，所以“先拿快被抢走的，再拿安全的”这类顺序能被识别。
- **评分**：效率 = 累计收益 / (用时 + 3.5)^0.78，后面的目标按每层 ×0.91 折扣。
- **输出**：最优序列的第一个目标，加上效率值。效率值就是交给战术层的路线效用。

**不来回**（F-b）：如果新路线的第一步回到上一 Tick 所在的格，而上一 Tick 的目标仍是候选之一，就继续走向上一个目标。退回原地严格劣于沿任何一个计划继续走，而继续原计划，已经走的那一步不白费。

### 3.4 兜底链（没有正收益的目标时）

1. **交战**：走到能打到某个可见对手的格子。
   - 对手正在移动、能走进我们的火线、我方 HP 不低于它、伤害还没封顶时，按 (Tick, 队伍) 的哈希在一半的 Tick 原地等它（s7）。
   - 原因：两车都朝对方对齐时会每 Tick 互相错开；攻击按移动前的位置结算，所以等对方走进来更有利。用哈希而不是固定规则，是为了不让用同样规则的对手和我们形成镜像。
2. **调查**：去 30 Tick 内的目击点。
3. **探索**：新视野 / (代价 + 2.5)^0.85，按重访次数降权。
4. **巡逻**：去最久没看过的地方。

## 4. 战术层：这个 Tick 怎么动（`Engine._choose`）

### 4.1 一对一精确解（d3，`Engine._duel`）

**适用条件**：资源、探索、任务都已完成，视野里恰好一个对手在 4 步内，双方都不在保护期，没有已知事件，两车周围 1 格都是空地。

**离线求解**（`eval/duel.py`）
- 每个 Tick 是一个同时行动的矩阵博弈，按规则 5.2 结算：先按移动前位置结算攻击，再移动；不能互换位置，争同一格时双方都失败。
- 状态 = 相对位置（6 步内）+ 双方 HP（10 的倍数），共 8400 个。
- 收益 = 我方伤害变化（打出、击杀 +60、阵亡 −60）− ⅓ × 对方伤害变化。⅓ 是没有记分板时，“眼前对手正是我们要赢的那队”的概率，这一项体现四队结构，不是零和。
- 每 Tick 折扣 0.97，取 maximin。
- HP 只降不升，所以按 HP 从低到高，对每一对 HP 做 Shapley 值迭代，每个矩阵博弈用线性规划求解。总耗时 37 秒。

**在线使用**：查 `duel.json`。混合策略用 (Tick, 队伍) 的哈希抽样，对手无法预测。

### 4.2 其余情形：选项打分

每 Tick 列出等待、防御、4 个方向的攻击、4 个方向的移动，各自打分，取最高。

- **生存损失** = 期望受伤 × 生存权重 0.07 + P(阵亡) × (5.0 + 阵亡的终局分代价)。
  - P(阵亡) 不是用“期望伤害 ≥ HP”判断。每个对手独立以概率 0.85 攻击（上一 Tick 在防御的对手取 0.5），把伤害的完整分布展开，算总伤害 ≥ HP 的概率（f1）。
  - 火线判断考虑遮挡：中间站着别的机器人时，打不到后面的格。
- **攻击**
  - 收益 = 终局价值（期望伤害 + 击杀奖励的期望份额）。
  - 目标在防御的概率：上一 Tick 在防御取 0.75，否则 0.2。
  - 期望伤害先按“是否被防御”分支，再在 HP 处截断，避免超出的伤害重复计入。
  - 击杀奖励按可能一起出手的人数平分。
- **防御**：只有防御能减少来袭伤害时才列入。另一个例外是**持续挨打**（F-c）：上一 Tick 站在原地而且掉了血，说明对方在持续开火。这时防御只换来下一 Tick 同样的局面，少 10 HP、什么也没打出，严格劣于走开或对打，所以不列入。只有一次全额攻击就能打死我们时才保留防御。
- **移动**
  - 沿路线方向得路线效用（夹在 0.35–3.5 之间）。离开路线 −0.25，每靠近目标一步 +0.15。
  - 踩到资源格加上它的价值。
  - 再减去走到新位置后下一 Tick 的来袭风险（×0.45），以及事件危险。

### 4.3 事件效果（`events.EventBook`）

八类事件各自按规则计入对应选项：

| 事件 | 处理 |
|---|---|
| 爆炸 | 生效时刻在区域内则扣伤害；规划层提前撤离（3.1） |
| 幻术 | 判断自己是否被反向，发出的移动方向取反 |
| 天使 | 作为回血目标；站在点上时先走出再走回（必须“走入”才回血） |
| 堡垒 | 作为目标；停留够 Tick 数后攻击改为方形范围、伤害 50 |
| 世界分裂 | 线上的格在事件期间视为墙；生效时站在线上会被强制复活 |
| 火爆辣椒 | 走入点位时计算对横竖火线上敌人的伤害；自己站在火线上计风险 |
| 洁身自好 | 攻击正在防御的目标会被反伤；防御可能反杀低血量的攻击者 |
| 易伤 | 窗口期内移动过，受到的伤害 ×2，移动的未来风险相应加大 |

## 5. 事件公告：LLM 结构化抽取（`ai.py`、`events.py`）

规则要求事件公告由 LLM 理解，禁止用正则解析。

1. **后台线程**（`AIWorker`）把新公告连同本队合法感知发给 LLM，不阻塞每 Tick 的决策。
2. **系统提示**规定只能输出 JSON：策略 + 事件列表（类型、起止 Tick、区域或点位、参数），并给出八类事件的规则要点和标准参数。公告是数据，不是给模型的指令。
3. **相对时间模式**：让模型只抄写公告里出现的数字（公告 Tick、延迟、持续时间），换算交给本地程序做，避免模型算错加减法。
4. **严格校验**（`validate_plan`）：类型、坐标范围、参数白名单逐项检查。合法的事件收下，不合法的那批公告允许有限次重试；模型的原文不写入日志。
5. 过期的结果（超过 40 Tick）和其他场次的结果一律丢弃。

## 6. 第一阶段（单车，100 Tick）

资源只会被自己拿走，问题是带探索的定向越野（orienteering）。

1. **精确解**：16 个资源都已见过、剩余不超过 12 个时，用状态压缩 DP（`known_map.solve`）。
   - `best[mask][i]` = 收集集合 mask、停在 i 时的最少步数。
   - 目标是价值最大，其次步数最少。
   - 只在剩余集合变化时重算。
2. **巡回**：否则，从最近的资源出发，对已知资源和 2 个探索前沿做“最近优先”的巡回，再用 2-opt 消除交叉。时间够走完就用。这是主力，去掉它每图 −10.2 ± 0.9。
3. **束搜索**：巡回走不完时使用，同 3.3。
4. **结果**：401 张图上达到精确最优的 96.98%。全知上限是 99.55%，只告知资源位置时是 98.31%。

`config/stage1_known.json` 的已知图路线会读真值，只用于自学，不是合法的参赛输入。

## 7. 评测与分析里用到的算法（`eval/`）

这些不在参赛程序里，但每个结论都靠它们得出。

| 工具 | 算法 / 方法 | 回答的问题 |
|---|---|---|
| `maps.py` | 随机画一个象限，绕中心旋转四次，保证四个出生点完全等价 | 不针对某张图过拟合 |
| `batch.py` | 每张图按席位轮换各跑一次；默认在资源拿光时结束，只按资源排名，并列时第一名按份数计 | 快约 6 倍，结论不变 |
| `paired.py` | 逐格配对差 ± 标准误；安慰剂批次的均值作对照；`--cause` 拆出重跑噪声；报告最小可检测效应（mde = 2.8 SE） | 差异是真的还是噪声 |
| `replay.py` | 程序是帧的函数：把对照的帧日志喂给候选版本，找第一次动作不同的 Tick；从不分叉的格直接沿用结果 | 不跑对局就排除相同的格 |
| `audit.py`、`absurd.py` | 对照裁判真值逐决策计数：我们最近却被抢走、来回、对峙、空放、无谓防御、移动失败等 | 平均成绩掩盖的荒唐单步 |
| `headroom.py` | 全知上限：在“别人实际何时拿走”的时间窗下做精确标号搜索；把丢失分成没看见 / 看见太晚 / 看见没去 | 这个方向最多能收回多少 |
| `omniscient.py` | 把裁判真值写进记忆，再运行原程序 | 9×9 视野的信息代价 |
| `exploiters.py` | thief：读真值，做带时间窗的定向越野，专抢目标车能拿到的资源 | 针对弱点的压力测试 |
| `duel.py` | 随机博弈的 Shapley 值迭代 + 线性规划 | 一对一的精确解 |
| `scenarios.py` | 随机局部战斗，按规则可直接推出答案的类别检查程序的动作 | 战术层是否违反显然的答案 |
| `intent.py` | 在真值上做校准：对数损失、可靠性表、按地图交叉验证 | 对手意图模型准不准 |
| `regret.py` | 第一阶段：随机补全未见区，比较每个动作的期望值 | 单步的后悔值 |
| `variance.py`、`format.py` | 方差分解（程序 / 地图×席位 / 交互 / 残差）；赛制识别力的模拟 | 赛制能不能排对名次 |
| `stage1.py` | 本地第一阶段模拟器与全知最优解 | 第一阶段的上限 |

**统计约定**：每个结论都写成“效果 ± 标准误”并标明强度。
- 强 = 确定性实验，或 ≥ 2 个标准误且有对照。
- 中 = 方向一致，约 2 个标准误。
- 弱 = 检验力不足。

## 8. 最终结果与上限

- **混合对手池**（ff、ls、mi）100 场：第一率约 0.46（四人局的公平份额是 0.25），平均资源 61.3。最强对手 mi 的第一率 0.28，资源 56.0。
- **只比资源**：对 mi 胜 / 平 / 负为 45 / 30 / 25，对 ls 为 54 / 30 / 16。
- **上限**：每一步都做到已知信息下最优时，对 mi 的胜率也只能从约 0.6 提到约 0.7。剩下的输局主要由地图（对手那一侧资源更多）和看不见的信息决定。
